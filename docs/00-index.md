The conceptual reading order is below. File numbers (`01-...`, `28-...`, etc.) are insertion order — newer docs were appended at higher numbers and slot into the conceptual flow as shown.

The **design for asset-subsystem Part B** (Part A — random per-asset DEKs, content-addressed `AssetStore`, `brainstorm://asset/` — already shipped). 28c. [The action surface](platform/63-action-surface.md) — **install an app → relevant new actions appear in other apps' menus** (the desktop-OS Share-sheet / Services / Quick-Actions model, made native). The mechanism already exists — the intents registry, the curated verb namespace, `intents.suggest`, the shell menu component ([26](platform/17-interoperability.md)) — this doc ships the missing wire as **two SDK framework elements** third-party devs also use: a *contributor* declaration (manifest intent + presentation metadata) and a *host* primitive (`useContributedActions` / `<ActionMenu>`), making `buildObjectMenuItems` suggestion-aware. Security by construction (a contribution **renders in the host, executes in the contributor's sandbox**, fail-closed — the [26](platform/17-interoperability.md) "no plugins for plugins" invariant holds); the hard part is restraint (relevance-gating, grouping, inline caps + "More…", trust tiers, per-app disable — so it never becomes a junk drawer). The composability payoff of the app platform — and the mechanism by which **AI stays optional** (the Agent app is one contributor among many; uninstall it and its actions vanish). OQ-AS-1..5.
28d. [MCP integrations](platform/64-mcp-integrations.md) — **connect external MCP servers so the Agent app can act beyond the vault** (GitHub, a database, a wiki, an API). Disambiguates the two "MCP"s first: the **dev MCP server** (Brainstorm-as-server for Claude Code during development, out of the product) vs. the **product MCP _client_** (this doc — Brainstorm consumes external servers). A new **MCP broker** core service is the *tool* analogue of [28](platform/22-ai-foundations.md)'s *provider* registry — lifecycle, `tools/list` discovery, capability gating, Tier-2 credential custody, egress, audit — projecting discovered tools into the harness's Tools layer ([28b §Layer B](platform/62-agent-harness.md)). Two transports on a sharp trust gradient: remote HTTP/SSE (egress-gated, [34](security/38-network-and-proxy.md)) and local stdio (**arbitrary local code** — explicit `mcp.spawn-local` consent, default-off). Tools obey the three-tier intersection ([25g](apps/55-agent-app.md)); tool *results* **and** *descriptions* are untrusted (the MCP-specific injection surface); writes confirm, reads may auto-run, all audit. Configured in **Settings → AI → MCP servers**, mirroring the provider-key panel. No new trust primitive. OQ-MCP-1..6.

28e. [Agent teams and orchestration](platform/69-agent-teams-and-orchestration.md) — from *a chat agent* ([25g](apps/55-agent-app.md)/[28b](platform/62-agent-harness.md)) to **a team of agents you manage and orchestrate** the way the dogfood team works — the concrete "orchestration spine" the [north star](foundations/67-ai-native-company.md) names. The dogfood persona *is* the spec (identity + specialty + a voice in a shared channel + a coordination discipline). **A vault is a company; agents are roster peers, not a chat feature** — so identity, @-mentions, assignment, audit, and revocation apply to them for free. New `brainstorm/Agent/v1` = a **persona shell over a capability ceiling** (persona prose = personality, skills = specialty, traits = routing/autonomy/memory; real permissions live in the `CapabilityLedger`). Each agent is a **real principal** — own Ed25519 key from day one (cheap, attributable, independently revocable); only multi-device sync is deferred (rides Collab). Orchestration is **assembly**: delegation (one `delegate` tool, made safe by *recursive* `intersectAgentTools` — a manager can never escalate a worker), assignment (task `assignee` = agent + a `Trigger`, **no lease ledger** because CRDTs merge), and **Chat** (agents as @-mentionable members). Governed by construction (every hop = broker → cap-check → audit row, so "what this agent did" is a query). Resolves OQ-AINC-1, takes a position on OQ-AINC-2; **post-beta, deliberately iterative**. OQ-AT-1..4.

30b-i. [Anytype import](platform/72-anytype-import.md) — a first-class switch-in from the closest structural peer (local-first, E2E-encrypted, objects + typed relations + block tree). Fixes the source-model → entity/property/body mapping, the JSON-export format choice (protobuf deferred), the fidelity matrix, and OQ-ANY-1..5 before code. Plugs into the doc-45 framework as one more *Source*; iteration `IE-10`.
30c. [Object selection and cross-app drag-and-drop](platform/65-object-selection-and-cross-app-dnd.md) — the desktop-OS connective tissue: **select objects in one app, drag them into another**. Analyses the hard truth [26](platform/17-interoperability.md) glossed — a drag crossing the per-app renderer boundary ([OQ-4](reference/11-open-questions.md)) **cannot** ride native HTML5 DnD (the `DataTransfer` doesn't cross processes; `webContents.startDrag` carries files only) — so cross-app drag is a **shell-mediated drag session**: shell stamps the source + owns the cursor-following ghost overlay + hit-tests the target window via `WindowIndex` + negotiates the drop semantic over the broker (types-and-location on hover, **reference-only** payload on drop) + re-checks capabilities fail-closed. The **target decides the meaning** (link / transclude / add-membership / set-property / move / copy / compose, defaulting least-destructive, declared not guessed); selection is unified behind the `selection` host service [26](platform/17-interoperability.md) promised but never shipped (it doubles as the drag payload); the wire format standardises on the shipped `application/vnd.brainstorm.entity+json` widened to `{ v, sourceApp, items[] }`. Every drag has a keyboard / cut-paste / action-surface [28c](platform/63-action-surface.md) twin. Direct-manipulation front-end to the intents bus, not a parallel system. OQ-DND-1..6.

30d. [Templates](platform/66-templates.md) — **one templating capability, inherited by every app** (not a Notes feature). Once objects are uniform (body + properties, [21](data/21-objects-and-collections.md)) a template is just *a pre-filled object you stamp copies of* — identical shape for a Task, Mail draft, Contact, Database row, Journal entry, or Note, so it is built **once** as a platform foundation. Three concepts on one data shape: **object templates** (applied by the shared create-flow — "new X from template Y"), **block/snippet templates** (applied by the `@brainstorm/editor` slash-menu — insert a fragment), and **vault templates** (Welcome-2's whole-vault starters, *already built, out of scope*). Resolves **OQ-LD-10 → own type `brainstorm/Template/v1`** (`templateKind` + `targetType`; tagged-entity rejected for query pollution); reuses the universal `root` body as the prototype, the [19](data/19-properties-and-schemas.md) layered precedence for scope (vault/type/collection-owned), and a default-template ladder (`view → collection → type → blank`, closing the doc-21 open sub-point). Two shared surfaces (create-flow picker + slash-insert/"save selection as template") mean per-app pickups are free; no new capability/trust surface. Refines Journal OQ-JR-1. Ships as the Stage 12 `templates` foundation that [§B11.10](implementation-plan.md) is gated on. OQ-TPL-1..4.

30e. [Mobile companion](platform/76-mobile-companion.md) — **design only, no development scheduled** — the vault in your pocket as **device N+1** on the unchanged Stage-10 + `brainstorm-sync` plane (no server-side change, no app platform on mobile, explicitly *not* parity per [01 §Non-goals](foundations/01-vision.md)). Four pillars in priority order: capture (share sheet → `Bookmark/v1`, quick note/task, photo/voice, a write-without-unlock HPKE **capture outbox**) · triage & reference (full-vault search + one stacked-layout object screen for every type) · reminders as **local** notifications (no push plane in v1) · lightweight editing (read-only bodies + append first; WebView-hosted `@brainstorm/editor` later). The load-bearing call: extract the portable TS vault core (Yjs + `@noble` + wire + sync engine + codecs) as **`@brainstorm/vault-core`** behind SqliteDriver/KeystoreBackend/SocketTransport adapter seams — desktop shell consumer #1, React-Native (Expo/Hermes, OQ-MOB-1 via the `MOB-0` spike) companion consumer #2; a forked crypto/sync core is rejected. Ships as the `MOB-0`–`MOB-8` ladder (a parallel contributor track, own repo like `../brainstorm-sync`); OQ-MOB-1..7.
